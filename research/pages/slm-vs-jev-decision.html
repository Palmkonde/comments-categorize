When to use an SLM with guarding, and when to use JEV

2026-11-06 · Follows Hallucination Math vs JEV · Applies to any task that maps an input to a fixed set of answers: classification, routing, triage, scoring, filtering. Every number links to the reference list, which says how it was checked.

Labels used in this page: verified quote read in the primary source · partial abstract only, third-party, or not re-read today · assumption no source: replace it with your own number · derived my own math from the cited inputs.

Step zero: first check whether plain rules (if-else, regex, lookups) are enough on your own labelled data. If they are, you need no model at all (section 0). A fixed set of answers does not mean a fixed rule: you need a model when choosing the answer means reading what the text means.

Short answer: if your task is "pick from a fixed set of answers" and rules are not enough, use JEV by default. Switch to a self-hosted SLM plus a guard model in one of three cases:

  1. JEV cannot do the job: text output, multi-step reasoning, fine-tuning, or on-prem (section 1).
  2. Your monthly volume \(N\) is above the price cut point \(N^*(T) \approx 1.4 \times 10^{10} / T\), where \(T\) is input tokens per item (section 2).
  3. On your own labelled data, the SLM makes enough fewer mistakes, or defers enough fewer items, to pay for its GPU (sections 2.3 and 3).

0. Do you need a model at all? (derived)

"Fixed answers" describes the output: a closed list of labels. It says nothing about how hard it is to get from the input to the right label. That is what decides between rules and a model.

ApproachWho maps input to answerWorks whenBreaks on
Plain if-else You do, by writing every rule The input is already structured (numbers, enums, form fields), or an exact surface pattern settles the label (contains a URL, exact blocklist match) Paraphrase, sarcasm, misspellings, slang, other languages, and context where one word is fine in one sentence and abusive in another. You cannot list every way to say the same thing.
Model + if-else The model reads the text and returns a label or probability. Your if-else turns that number into an action. The label depends on meaning, not on exact words Costs money and time per call. It can still be wrong or over-confident, so you need thresholds and a human-review band.

Most real systems use both. TypeSafe's own docs tell you to "combine the results with logic in your code"[3] and suggest confidence thresholds of 0.7 and 0.3[5]. Those thresholds are an if-else on top of JEV's output. This repo does the same in sections/common.py: flag <= low means Auto-keep, flag >= high means Auto-flag, and anything between goes to Human review.

A common layout is three layers:

  1. Rules first. Cheap, deterministic checks catch the obvious cases (a known spam link, an empty comment).
  2. The model only sees what the rules could not settle. That lowers your monthly volume \(N\), so every cost in section 2 drops with it.
  3. Thresholds on the model's output decide: act automatically, or send to a person.

How to decide: on the same labelled set as section 3, measure your rules' accuracy, and how many items they cover. If rules alone reach your accuracy target, stop and use no model. If they cover only some items with high accuracy, keep them as a pre-filter and send the rest to a model.

No external source for this section. It is ordinary engineering practice plus the two TypeSafe quotes above. Section 5 adds it as the first line of the decision rule.

2. Cost per item

For each item, the expected cost is (derived; it follows the expected-cost decision principle[14]):

\[ C = c_{\text{call}} + P(\text{automatic answer wrong})\cdot c_{\text{err}} + P(\text{deferred})\cdot c_H \]
  • \(c_{\text{call}}\) is the API or GPU cost of one call.
  • \(c_{\text{err}}\) is the cost of one wrong automatic answer.
  • \(c_H\) is the cost of one item sent to a person or a slower system.

2.2 Price-only break-even (derived)

\[ N^*(T) = \frac{F_{\text{GPU}}}{T \cdot 0.042/10^6} = \frac{\$587.50}{T \cdot 4.2\times10^{-8}} \approx \frac{1.4 \times 10^{10}}{T}\ \text{items / month} \]
Tokens per item \(T\)Typical input (illustrative)JEV cost / itemBreak-even \(N^*\) / month
100A short text, one question$0.0000042~140M
500A message plus a few questions$0.000021~28M
1,000A ticket or email with context$0.000042~14M
5,000A long document or an agent trace$0.00021~2.8M
20,000Very long input$0.00084~0.7M

Below \(N^*\), JEV is cheaper on price alone. Above it, one L4 is cheaper only if it can keep up. At 14M items a month, that is about 5.4 items per second on average, with higher peaks. Shorter questions lower \(T\) and raise \(N^*\). Asking several questions in one call also lowers cost: TypeSafe's cookbook found that one call with N questions gives the same answers as N calls, and was cheaper and faster.[7]

2.3 Deferrals and errors usually matter more than the price (derived)

Let \(\Delta\text{err}\) and \(\Delta\text{defer}\) be how much lower the SLM's error rate and deferral rate are. Let \(\Delta F\) be its extra monthly cost (GPU minus JEV). The SLM wins when its savings beat that extra cost:

\[ \text{choose SLM} \iff N\,(\Delta\text{err}\cdot c_{\text{err}} + \Delta\text{defer}\cdot c_H) \;\gt\; \Delta F \qquad\Rightarrow\qquad c_H^{*} = \frac{\Delta F}{N\cdot\Delta\text{defer}} \quad(\text{if } \Delta\text{err}=0) \]

Example below with \(T = 1{,}000\) tokens per item, 1× L4, and an SLM that defers 2 percentage points fewer items.

Items / month \(N\)JEV cost\(\Delta F\)Break-even \(c_H^{*}\)Reading
100k$4.20$583.30$0.29The SLM pays off only if a deferral costs more than about 29 cents

So the deciding numbers are \(\Delta\text{err}\) and \(\Delta\text{defer}\). Only a labelled test can measure them.

3. The real cut point: measured accuracy and deferral rate

  1. Hand-label \(n\) items from your real data.
  2. Run JEV and the SLM + guard on the same items.
  3. Compare the error rate at a fixed share of automatic answers, and the ECE. Use McNemar's test. Dietterich's comparison of tests for classifiers found McNemar's test has low type I error, and recommends it when each algorithm can be run only once.[15]

Sample size per group for comparing two proportions, using the normal approximation (95% two-sided, 80% power, accuracy around 85%):[16]

\[ n \approx \frac{(z_{0.975} + z_{0.8})^2\,\big[p_1(1-p_1) + p_2(1-p_2)\big]}{\Delta^2} \approx \frac{(1.96 + 0.84)^2 \cdot 2 \cdot 0.85 \cdot 0.15}{\Delta^2} \]
Gap to detect \(\Delta\)\(n\) per groupMeaning
10 points~200Enough only to catch large differences
5 points~800Typical size for a serious model choice
3 points~2,200Needed to separate close models

This is the unpaired formula. A paired design (both systems on the same items) usually needs fewer. How many fewer depends on how often the two systems disagree, which you only learn by running them. The formula is the standard normal approximation. The cited calculator implements it[16] but does not print the formula, so status is partial.

4. Things that move the cut point

FactorFavoursEvidence
Your label set vs guard model categoriesDepends

Built-in categories: off-the-shelf guard models cover safety harms only.

  • Llama Guard 3: 14 categories, such as S1 Violent Crimes, S10 Hate and S13 Elections.[9]
  • ShieldGemma: sexually explicit content, hate speech, dangerous content, harassment, violence, and obscenity and profanity.[11]

Other label sets: for intent, routing, triage, sentiment, spam or topic, the guard model does not apply off the shelf. The SLM must do the classification itself, with your prompts, labels and calibration. Llama Guard supports "zero-shot or few-shot prompting with diverse taxonomies",[10] but you have to test custom categories yourself.

Low-resource languagesTest first The independent preprint reports JEV's accuracy falling in many low-resource languages.[8] It tested jev-1.13.0. Version 1.14 claims "Better multilingual support".[17]
Many yes/no labels per item (multi-label noul)SLM (slightly) Preprint ECE for multi-label noul: JEV 0.168 vs Qwen 0.119, lower is better.[8] Single noul and choice were better calibrated with JEV.
Option orderTest first "Jev leans toward the option that comes first." TypeSafe's fix: "reorder the options to double check that the answer stays consistent."[4]
SpeedJEV "End-to-end response time is 70ms-500ms."[1] This is the vendor's own measurement ("run from our laptops on the West Coast"). SLM + guard needs two model passes on your own hardware.
ThresholdsEither TypeSafe: "Good starting thresholds are 0.7 and 0.3 ... Give the band between 0.3 and 0.7 its own outcome in code."[5] To set them from your own costs, see section 7 of the math page.
Version driftSLM "An alias moves when a new release ships, so its answers can change without any change to your code." Their advice: "send that version's ID instead of the alias."[2] A self-hosted SLM changes only when you change it.
Rate limitsCheck "Limits are measured in tokens per second and requests per second." "Higher limits are available on custom and enterprise plans."[2] A self-hosted SLM is limited only by your hardware.

5. Decision rule (derived from sections 0–3)

if rules alone hit your accuracy target on labelled data:              no model (if-else / regex)
# otherwise keep rules as a pre-filter and send the rest below
elif needs text output / multi-step reasoning / fine-tuning / on-prem: SLM + guard
elif labelled test: N·(Δerr·c_err + Δdefer·c_H) > ΔF:                   SLM + guard
elif N > N*(T) ≈ 1.4e10 / T and your GPUs keep up:                      SLM + guard (on price)
else:                                                                  JEV

If you already own the GPU (derived): the fixed cost \(\Delta F\) is no longer the $587.50/month rental. It shrinks to power, your team's time to run the model, and whatever else the GPU could be doing. \(N^*\) falls with it, so the price branch points to self-hosting much sooner. The labelled test (section 3) still decides on accuracy.

For fixed-answer tasks below \(N^*(T)\), JEV wins on price. It also wins overall, unless a labelled test shows the SLM makes meaningfully fewer errors or deferrals. Run that labelled test on your own data before you choose.
